核心知识点速览

知识点 要点
微服务是什么 将单体拆分为多个独立服务，各自独立部署/扩展
Spring Cloud 微服务治理全家桶（注册/调用/网关/熔断/配置）
Nacos 注册中心 + 配置中心，AP+CP 混合
Feign 声明式 HTTP 客户端，像调本地方法一样调远程
Gateway API 网关，路由+过滤+断言，替代 Zuul
Sentinel 流量控制/熔断降级/热点限流
LoadBalancer 客户端负载均衡，替代 Ribbon

一、微服务架构概述

1.1 单体应用 vs 微服务

对比维度 单体应用 微服务
部署 一个包部署 每个服务独立部署
扩展 整体扩展（浪费资源） 按需扩展（精确扩展）
技术栈 单一语言 各服务可用不同语言
团队协作 改同一个项目，冲突多 各团队维护各自服务
运维复杂度 低 高（需要注册中心、配置中心、网关等）

1.2 微服务核心组件

一句话各组件：

  • Nacos — 统一注册中心，让 A 服务能找到 B 服务
  • Feign — 远程调用，像调本地方法一样调另一个服务
  • Gateway — 统一入口，所有请求先进网关再转发
  • Sentinel — 流量控制，防止服务被冲垮

保护机制 阈值保护 自我保护模式
控制台 功能丰富（Web UI） 基本
健康检查 心跳 + TCP/HTTP 检测 心跳

五、Sentinel（流量控制）

5.1 核心概念

概念 说明
流量控制 限制接口的调用频率（QPS 或线程数）
熔断降级 接口异常率超过阈值，自动熔断
热点规则 对指定参数限流（如商品 ID=100 频繁请求）
系统保护 根据 Load/RT/线程数自适应保护
规则持久化 规则推送到 Nacos 或文件，避免重启丢失

Q1：Spring Cloud 核心组件一句话说清楚？

Q2：Feign 和 Dubbo 的区别？

对比维度 Feign Dubbo
协议 HTTP（RESTful） TCP（二进制，自定义协议）
性能 较低（HTTP 重） 高（TCP 轻量）
跨语言 天然支持 需多语言 SDK
适用场景 Spring Cloud 体系 高性能内部调用
负载均衡 Spring Cloud LoadBalancer 内置多种策略

Q3：Gateway 和 Nginx 的区别？

对比维度 Gateway Nginx
定位 微服务 API 网关 反向代理 + 负载均衡
层级 应用层（Java） 网络层（C）
性能 较低（Java 处理） 极高（epoll 事件驱动）
集成度 与微服务深度集成 需要配合其他组件
配置方式 代码/配置文件 纯配置文件

最佳实践： Nginx 在最外层做负载均衡和 HTTPS 终结，Gateway 在内层做微服务路由和鉴权。
