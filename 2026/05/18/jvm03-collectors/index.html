垃圾收集器：从Serial到G1、ZGC

核心知识点速览

知识点 要点
收集器演进 Serial → ParNew/Parallel → CMS → G1 → ZGC/Shenandoah
分代收集器 Serial、ParNew、Parallel Scavenge、Serial Old、Parallel Old
CMS 标记-清除，四阶段，并发标记，碎片 + 浮动垃圾
G1 Region 化堆，可预测停顿，Mixed GC，SATB
ZGC 染色指针 + 读屏障，停顿 <1ms，JDK21 分代
选型 小堆 Parallel，大堆 G1，超大堆/低延迟 ZGC

一、先看全景图

三个指标先摆清楚，所有选型都是在它们之间取舍：

二、分代收集器

2.1 Serial / Serial Old

  • 单线程，GC 时所有用户线程停顿
  • 新生代复制、老年代标记-整理
  • 优点：简单、内存开销小、没有线程切换开销
  • 现在主要用于客户端模式或几十 MB 的小堆

2.2 ParNew

  • Serial 的多线程版本，新生代并行复制
  • 曾经是 CMS 的唯一搭档（CMS 只能配 ParNew 或 Serial）

2.3 Parallel Scavenge / Parallel Old

  • 关注吞吐量而不是停顿时间
  • 有自适应调节：-XX:+UseAdaptiveSizePolicy，不用手工指定新生代大小
  • 适合后台批处理、离线计算这种”慢一点没关系，别浪费时间”的场景

2.4 CMS（Concurrent Mark Sweep）

以”最短停顿”为目标的收集器，老年代用标记-清除。

四个阶段：

缺点很明确：

  • CPU 敏感：并发阶段会占用线程（默认 (CPU+3)/4 个），核心少的时候用户程序明显变慢
  • 浮动垃圾：并发清除期间新产生的垃圾只能等下一次
  • 碎片问题：标记-清除不整理，大对象可能分配失败，触发 Full GC（Serial Old 兜底）
  • Concurrent Mode Failure：并发标记还没完成，老年代就满了，只能退化成单线程 Full GC，停顿非常长

JDK9 起 CMS 被标记废弃，JDK14 移除。

三、G1：面向大堆的分区收集器

3.1 核心变化：Region

这样回收就不必整堆回收，而是挑垃圾最多的 Region 优先回收——Garbage First 的名字就是这么来的。

3.2 停顿可预测

G1 允许你设一个目标停顿时间：

G1 会维护每个 Region 的”回收价值”（能回收多少垃圾 / 需要多少时间），在目标时间内挑性价比最高的 Region 回收。这是它和 CMS 最大的思路差异：CMS 管不了停顿，G1 把停顿当成约束条件。

3.3 回收流程

3.4 G1 的几个关键点

  • RSet（Remembered Set）：每个 Region 记录”谁引用了我”，回收单个 Region 时不用扫全堆
  • SATB：并发标记用原始快照，删除引用时记录下来，保证不漏标
  • 巨型对象：超过 Region 一半的对象直接进 Humongous，可能横跨多个 Region，这类对象多的时候很影响性能
  • 不适合的场景：堆很小（不如 Parallel）、要求极致吞吐（G1 的写屏障有开销）

四、ZGC：把停顿压到 1ms 以内

4.1 怎么做到的

核心是两点：染色指针 + 读屏障。

对比 G1 的写屏障（只在赋值时插入），读屏障是”读的时候处理”，所以 ZGC 可以做到并发移动对象——对象在搬家的同时，用户线程照常读，读到旧地址就自动转发到新地址。

4.2 阶段

除了极短的初始标记和最终标记，几乎全程并发，停顿与堆大小、存活对象数量基本无关。

4.3 代价

  • 吞吐量下降：读屏障有开销，一般比 G1 低 5%~15%
  • 内存占用高：需要多色指针映射、转发表
  • 需要较大堆：官方建议堆至少几百 MB 以上才划算
  • JDK 11 实验性引入，JDK 15 转正，JDK 21 推出分代 ZGC（解决”全堆回收效率低”的问题）

五、怎么选

我在项目里实际配的就是 G1 + 200ms 目标停顿，够用且不用太操心。真正要调优的时候，先看 GC 日志，再决定动哪个参数——而不是一上来就背一堆参数往上堆。

六、面试重点清单

  • 说得出几个收集器？各自用在哪一代、什么算法？
  • 吞吐量和停顿时间怎么取舍？哪些收集器偏向哪个？
  • CMS 的四个阶段？为什么需要重新标记？
  • CMS 有什么缺点？Concurrent Mode Failure 是怎么产生的？
  • 为什么 CMS 被废弃？
  • G1 的 Region 是什么？为什么叫 Garbage First？
  • G1 怎么做到”可预测停顿”？
  • G1 的 RSet 解决什么问题？和卡表什么关系？
  • G1 的 Young GC 和 Mixed GC 有什么区别？
  • ZGC 靠什么把停顿做到 1ms 以内？染色指针和读屏障分别干什么？
  • 生产环境你怎么选收集器？为什么 JDK9 之后默认 G1？
  • 什么时候会发生 Full GC？怎么减少？

小结

收集器的演进其实就一条主线：在”停顿”和”吞吐”之间找平衡，同时让回收粒度越来越细。
