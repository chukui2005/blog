一、运行时数据区

先记住一张图：

1.1 程序计数器（PC Register）

  • 记录当前线程正在执行的字节码行号
  • 线程私有，每个线程一份
  • 唯一不会抛 OOM 的区域（规范里没规定它的内存限制）

1.2 虚拟机栈

每个方法调用创建一个栈帧，栈帧入栈出栈对应方法执行结束。

两种异常：

  • StackOverflowError：栈深度超过限制（递归没写终止条件最典型）
  • OutOfMemoryError：栈扩展时申请不到内存

用 -Xss 设置单线程栈大小，默认 1MB 左右（和平台有关）。

1.3 本地方法栈

给 native 方法用的，HotSpot 里和虚拟机栈合并实现，异常类型一样。

1.4 堆

  • 存放对象实例和数组，几乎所有对象都在这
  • 线程共享，是 GC 的主战场
  • 分代划分（以 G1 之前的分法为例）：新生代 = Eden + Survivor0 + Survivor1，默认比例 8:1:1；老年代
  • -Xms 初始堆大小、-Xmx 最大堆大小，生产建议设成一样，避免反复扩缩容

一个细节：TLAB（Thread Local Allocation Buffer）。每个线程在 Eden 里预先分一小块私有区域，分配对象优先在自己的 TLAB 里做，不用每次都 CAS 抢指针。TLAB 用完才回到共享 Eden 走同步分配。

1.5 方法区 / 元空间

存的是类的元信息：类结构、字段描述、方法字节码、运行时常量池、静态变量（JDK7 后静态变量搬到了堆里）。

版本演进要记清楚：

为什么换元空间？永久代大小难调、容易 PermGen space OOM，而且和堆共用内存，类加载多（大量动态代理、热部署）就容易撑爆。元空间用本地内存，理论上只受机器内存限制。

1.6 直接内存

不是 JVM 规范里的区域，但很常用：

  • NIO 的 DirectByteBuffer、Netty 的池化内存都在这
  • 优点：零拷贝，避免堆内到堆外的复制
  • 缺点：分配回收成本高，不受 -Xmx 限制但受 -XX:MaxDirectMemorySize 限制
  • 常见事故：堆内存很稳，但机器内存被吃光，就是这个没管

四、各区域对应的 OOM

面试常问”哪里会 OOM”，直接对着区域说：

区域 异常 典型原因
堆 java.lang.OutOfMemoryError: Java heap space 内存泄漏、大对象、缓存无上限
堆 GC overhead limit exceeded GC 花了 98% 时间却只回收不到 2%
元空间 Metaspace 动态生成类过多（CGLIB、反射、热部署）
直接内存 Direct buffer memory NIO 分配过多，没释放
线程 unable to create new native thread 线程数超系统限制
栈 StackOverflowError 递归过深

小结

这一篇是全系列的地基，后面讲 GC、类加载、调优都要回到这张图上来。

记住三条：

  1. 线程私有 vs 共享 —— 决定了哪里会并发、哪里要加锁
  2. 堆分代 + TLAB —— 决定了对象分配和 GC 的行为
  3. 对象头里的 Mark Word —— 决定了锁升级、hashCode、GC 年龄怎么存
