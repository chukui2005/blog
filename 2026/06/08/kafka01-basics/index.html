Kafka基础与架构

核心知识点速览

知识点 要点
Kafka是什么 分布式消息队列/流处理平台，高吞吐、可持久化
核心架构 Producer → Topic (Partition) → Consumer Group
存储模型 顺序写 + 页缓存，O(1)磁盘读写
分区与副本 Partition分片 + Replication副本
消息模型 发布订阅 + 消费组逻辑队列

一、Kafka整体架构

核心组件

组件 说明
Broker Kafka服务器节点，集群由多个Broker组成
Topic 主题，消息的逻辑分类
Partition 分片，每个Topic可分成多个Partition实现并行
Replica 副本，每个Partition有Leader+Follower保证高可用
Consumer Group 消费组，组内消费者协同消费，实现负载均衡
Offset 偏移量，消息在Partition中的唯一位置

二、Topic与Partition

2.1 分区机制

  • 每个Partition是有序的、不可变的消息序列
  • Partition内部保证顺序，Topic全局不保证
  • 分区数决定最大并行度（一个分区最多被一个消费者消费）

2.2 分区的优势

特性 说明
水平扩展 增加分区 → 增加消费者 → 提升吞吐
负载均衡 分区分布在多个Broker上
顺序保证 同一分区内消息严格有序
并行消费 N个分区可被N个消费者并行消费

2.3 分区数设置建议

三、副本机制（Replication）

3.1 ISR机制（In-Sync Replicas）

  • ISR：与Leader保持同步的副本集合
  • Leader：负责读写，从ISR中选举
  • Follower：从Leader拉取数据同步
  • HW（High Watermark）：ISR中所有副本都确认写入了的offset
  • LEO（Log End Offset）：每个副本的日志末端位置

3.2 ACK参数

ack值 含义 吞吐 可靠性
0 不等待确认 最高 可能丢
1 Leader写入即返回 高 中
-1/all ISR全部写入才返回 低 最高

四、消费组机制

4.1 消费组模型

4.2 三种消息传递语义

语义 说明 实现方式
At most once 最多一次，可能丢 自动提交offset，消费前提交
At least once 至少一次，可能重复 处理完再提交offset + 幂等
Exactly once 精确一次 事务 + 幂等 + 原子性写入外部系统

生产推荐： At least once + 消费端幂等

五、存储模型：顺序写 + 页缓存

5.1 文件存储结构

  • 消息追加到Segment末尾（顺序写），磁盘顺序写 ≈ 内存写
  • 利用OS页缓存（Page Cache），不走JVM堆内存
  • 索引文件采用稀疏存储（每4KB消息存一个索引），节约内存
  • 日志段达到大小/时间阈值后关闭，新消息写入新Segment

5.2 零拷贝（Zero Copy）

Kafka的高吞吐核心：顺序写 + 零拷贝 + 页缓存 + 批量压缩

六、Kafka vs RabbitMQ 初步对比

对比项 Kafka RabbitMQ
定位 分布式流处理平台 消息中间件
协议 自定义协议 AMQP
吞吐量 百万级/秒 万级/秒
消息模型 Pull模式（消费者主动拉取） Push + Pull
顺序保证 分区内顺序 单队列顺序
消息路由 按分区策略 Exchange + Routing Key
适用场景 大数据/日志/流处理 业务消息/事务性消息
开发语言 Java/Scala Erlang
