RPC与远程调用：Feign原理与超时重试的坑

核心知识点速览

知识点 要点
Feign 本质 声明式 HTTP 客户端，靠动态代理生成实现
核心链路 动态代理 → Contract 解析 → 编码 → 负载均衡 → 发送 → 解码
负载均衡 轮询、随机、权重、最小连接数、一致性哈希
超时设计 调用方超时 < 服务提供方处理时间 + 网络延迟
重试风险 非幂等接口重试 = 数据重复，重试还会放大流量
Feign vs Dubbo HTTP 文本协议 vs 二进制私有协议 + 长连接

一、Feign 是什么

一句话：让你像调本地方法一样调 HTTP 接口。

没有实现类，但能直接 @Autowired 注入使用。靠的就是动态代理。

五、Feign 和 Dubbo 怎么选

这是面试常问的对比题，核心差异在协议层：

维度 Feign（HTTP） Dubbo
协议 HTTP/1.1（文本） dubbo 私有协议（二进制）
连接 短连接（可配连接池） 长连接，多路复用
序列化 JSON（文本，体积大） Hessian2 / Protobuf
性能 一般（文本解析开销） 高（二进制，头部小）
治理 依赖 Spring Cloud 生态 自带丰富治理能力（路由、限流、降级、泛化调用）
跨语言 天然支持 需 Triple 协议 / gRPC
调试 用 curl/Postman 直接测 需要专用工具

补充一句：Dubbo 3 的 Triple 协议已经兼容 gRPC 和 HTTP/2，性能优势和跨语言的短板都在补，所以”Dubbo 只能内网用”这种说法已经不准确了。
