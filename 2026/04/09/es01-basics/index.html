ElasticSearch基础与核心概念

核心知识点速览

知识点 要点
ES是什么 基于Lucene的分布式搜索引擎，RESTful接口，近实时
核心概念 索引/文档/字段/映射/分片/副本
倒排索引 Term Dictionary + Posting List，搜索性能核心
ES vs MySQL 全文检索 vs 事务存储，常配合使用
分词器 Standard / IK中文分词
近实时 refresh 1s 才可见，不是强实时

一、ElasticSearch是什么

特性 说明
分布式 天然集群，水平扩展
近实时 写入后约1s可查询（refresh）
RESTful 所有操作走HTTP JSON API
高可用 分片副本自动故障转移
多租户 一个集群多个索引

二、核心概念

2.1 与MySQL类比

MySQL ElasticSearch 说明
Database Index（索引） 逻辑命名空间
Table Type（类型，7.x废弃） ES 8.x 已移除
Row Document（文档） 一条JSON数据
Column Field（字段） 文档中的键值
Schema Mapping（映射） 字段类型定义
分库分表 Shard（分片） 数据水平切分
主从备份 Replica（副本） 冗余备份

2.2 分片与副本

概念 作用
主分片（Primary Shard） 数据实际存储单元，参与写入
副本分片（Replica） 主分片的完整拷贝，读负载分担 + 故障转移
节点（Node） 一台ES实例，可分角色（master/data/ingest）

三、倒排索引（核心中的核心）

3.1 正排 vs 倒排

3.2 倒排索引结构

为什么快？ 查询时先二分/FST定位 Term，再取 Posting List 做交集/并集，完全绕开全文档扫描。MySQL 的 LIKE ‘%xxx%’ 无法用 B+Tree 索引，只能全表扫。

四、ES vs MySQL 怎么选

对比项 MySQL ElasticSearch
事务 ✅ ACID ❌ 不支持
全文检索 ❌ LIKE 全表扫 ✅ 倒排索引
模糊查询 弱 ✅ 强
聚合分析 一般 ✅ 强大
数据一致性 强一致 近实时（最终一致）
更新/删除 快 慢（标记删除+段合并）
典型场景 交易、核心业务数据 搜索、日志、监控、分析

五、分词器（Analyzer）

5.1 分词流程

5.2 常用分词器

分词器 说明 适用
Standard 默认，按空格/符号切分，英文友好 英文场景
Keyword 不分词，整体作为一个词 精确匹配（ID、状态）
IK（中文） 智能中文分词，支持自定义词典 中文搜索必备
IK分词模式 ik_smart（粗粒度）/ ik_max_word（细粒度） 索引用max_word，搜索用smart

⚠️ 分词一致性陷阱：索引分词器（细粒度）≠ 搜索分词器（粗粒度），否则搜不到。例如索引用 ik_max_word，查询一般也用同一分词器。

六、基本操作（REST API）

6.1 索引操作

字段类型 说明
text 全文类型，分词后倒排索引，用于搜索
keyword 精确类型，不分词，用于过滤/排序/聚合
integer/double 数值
date 日期
boolean 布尔
object / nested 对象 / 嵌套对象

6.2 文档操作

七、面试重点清单

  1. 倒排索引：Term Dictionary（FST）+ Posting List，为什么比LIKE快
  2. text vs keyword：分词 vs 不分词，搜索/过滤/排序怎么选
  3. 分片副本：主分片数创建后不可变，副本可调，主副不能同节点
  4. 近实时：refresh 1s 机制，不是强一致
  5. ES vs MySQL：全文检索/聚合 vs 事务，组合使用
  6. 中文分词：IK分词器、ik_smart vs ik_max_word、自定义词典
