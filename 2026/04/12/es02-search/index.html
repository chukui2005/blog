ElasticSearch查询与聚合

核心知识点速览

知识点 要点
match vs term 全文检索分词 vs 精确匹配不分词
bool复合查询 must/should/must_not/filter 组合
相关性打分 BM25算法（词频+文档频率）
filter缓存 不参与打分，结果可缓存，性能高
聚合分析 Metric + Bucket，分组统计
深分页 from+size有上限，scroll / search_after

一、查询DSL基础

1.1 全文检索：match

1.2 精确匹配：term

查询 类型 是否分词 场景
match text ✅ 分词 全文搜索
term keyword ❌ 不分词 精确匹配（状态、ID、品牌）
terms keyword ❌ IN 查询（多值匹配）
range 数值/日期 ❌ 范围查询 gt/gte/lt/lte
wildcard keyword/text ❌ 通配符（性能差，慎用）
prefix keyword ❌ 前缀查询

二、复合查询：bool

性能要点：能用 filter 就用 filter —— 不计算相关性，且相同条件的查询结果会被 ES 缓存，命中缓存时性能提升巨大。

三、相关性打分：BM25

3.1 打分公式（BM25，ES 5+ 默认）

3.2 影响打分的因素

因素 影响
词频TF 出现次数越多分越高（有饱和上限）
逆文档频率IDF “华为” vs “的”——常见词权重低
字段权重 boost 可手动加权（title 权重大于 description）
文档长度 短文档匹配更相关

四、聚合分析（Aggregation）

4.1 两类聚合

类型 作用 例子
Metric（指标） 数值计算 avg/max/min/sum/cardinality
Bucket（分桶） 分组 terms/range/date_histogram

4.2 实战案例

面试点：聚合底层依赖倒排索引+列式存储（doc_values），keyword/数值字段默认开启 doc_values 才能聚合；text 字段默认不能聚合（需 fielddata，慎用）。

五、深分页问题（高频面试题）

5.1 问题根源

5.2 三种分页方案对比

方案 原理 优点 缺点 适用
from+size 每页跳跃 简单，支持随机跳页 深分页性能差，上限1万 浅分页（<1万）
scroll 生成快照游标，批量拉取 适合大数据量导出 快照不实时，占资源 数据导出、全量同步
search_after 用上一页最后一条的排序值定位 实时、性能稳定、无限翻页 不能随机跳页 深分页实时搜索

必须带 tiebreaker：排序字段值相同（如价格相同）时，必须加 _id 等唯一字段做次级排序，否则可能漏数据/重复。

六、查询性能优化

优化手段 说明
filter代替must 不打分 + 结果缓存
限制返回字段 _source 只取需要的字段，减小IO
避免 wildcard/script 无法用倒排索引，性能杀手
合理分片 分片过大/过小都影响查询
冷热分离 热数据SSD，冷数据压缩归档
索引别名+重建 字段类型改不了 → 重建索引切别名
查询超时 timeout 参数防止拖垮集群

七、面试重点清单

  1. match vs term：分词与否，text vs keyword
  2. bool四子句：must打分/filter缓存/must_not排除，filter优先
  3. BM25：TF+IDF+长度归一化，boost加权
  4. 聚合：Metric + Bucket、doc_values、text不能聚合
  5. 深分页：from+size上限1万、scroll导出、search_after实时深翻页（必须tiebreaker）
  6. 性能：filter缓存、_source裁剪、禁wildcard
