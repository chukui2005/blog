我为什么卸载了 Navicat 和 Tiny RDM

👉 GitHub 地址

先说结论

以前电脑上长期装着两个数据库客户端：Navicat 管 MySQL，Tiny RDM 看 Redis。

不是说它们不好。Navicat 功能确实全，Tiny RDM 也算轻量。但两套界面、两套快捷键、两个更新弹窗，天天来回切，时间久了是真的烦。

后来试了 dbx，用了大概一周，我把上面两个都卸了。

第一眼：简约，但不简陋

dbx 的 UI 是那种很克制的风格。没有花哨的渐变，没有堆到屏幕边缘的按钮，信息密度刚刚好：左边连接树和 schema 浏览，中间 SQL 编辑器，右边结果集。第一次打开基本不用看文档就知道该点哪儿。

细节上也能看出是天天自己在用的人做的：

  • 暗色模式会和系统标题栏同步，不是那种”应用是黑的、标题栏是白的”的割裂感
  • 编辑器有 9 套主题，SQL 高亮、格式化、自动补全都齐全，Cmd/Ctrl + Enter 直接执行当前语句或者选中的 SQL
  • 查询历史会持久化，标签页关掉重开还在，写了一半的 SQL 不会丢
  • 中英西三语界面

对每天要开十几次数据库客户端的人来说，界面顺眼这件事，比多十个用不上的功能重要得多。

25 MB，一个二进制文件

这是我最喜欢它的一点，也是它和同类工具最本质的区别：

  • 安装包 25 MB 左右，跨平台，macOS / Windows / Linux 都有原生客户端
  • 不用装 Java JRE，不用配 Python 虚拟环境，也不打包 Chromium
  • 下载、安装、连库，就这三步，冷启动基本秒开

对比一下就很明显：DBeaver 依赖 Java 运行时，装完动辄几百兆；TablePlus 轻是轻，但核心功能在付费版；Navicat 就不用说了，授权费摆在那儿。

dbx 是用 Rust 写的，Apache-2.0 开源，整个应用就是一个小二进制。双击就开，不需要为”打开一个数据库客户端”这件事付出额外的系统成本。

小体积，功能却一点没少

用之前我以为这么轻的工具，功能肯定砍得厉害，结果并不是。

数据库覆盖得离谱。 MySQL、PostgreSQL、SQLite、Redis、MongoDB、DuckDB、ClickHouse、SQL Server、Oracle、Elasticsearch、MariaDB、TiDB、OceanBase、StarRocks 这些都是原生支持，国产库里的达梦、人大金仓、openGauss、GaussDB、OceanBase 也都在列。官方说法是 100+ 种，还能通过 agent 模式接 H2、Snowflake、Trino、Hive、DB2 这些 JDBC 连接。

这意味着什么？以前查 MySQL 开一个软件、看 Redis 开另一个、连达梦又得找厂商工具，现在一个窗口全搞定。

数据网格做得挺细。 大结果集是虚拟滚动的，不卡；单元格支持行内编辑，保存前会先给你预览 SQL；筛选、排序、分页、列宽自适应这些是基本操作，导出还能直接出 CSV、JSON、Markdown、XLSX 或者 INSERT 语句。

Schema 相关的工具很全。 ER 图可视化表关系、执行计划可视化、跨连接的 schema diff、字段级血缘分析、大库里的对象搜索——这些以前要么在付费工具里，要么得单独找工具。

还有几个我实际用得很爽的点：

  • 表结构和数据可以直接在库之间迁移，做测试库同步很方便
  • 支持从 Navicat / DBeaver 直接导入连接配置，迁移成本几乎为零
  • 拖一个 Parquet / CSV / JSON 文件进去就能直接预览，底层是 DuckDB
  • SSH 隧道支持密钥和密码两种方式，连跳板机后面的库不用额外开隧道
  • 危险操作（DROP、TRUNCATE 之类）有二次确认，连接还能按颜色区分，生产库标红，一眼就知道自己在哪

不只是数据库：消息队列也有控制台

这一点我觉得是它和其他数据库客户端的最大差异。

做 Java 后端的应该都有体会：调一个订单链路，MySQL 要看数据、Redis 要看缓存、Kafka 要看消息有没有积压，三个软件来回切。

dbx 里这些是放在一起的：

  • Kafka / RocketMQ / RabbitMQ / Pulsar：topic、消费组、消息浏览、消息查询和链路追踪、broker 监控
  • MQTT：topic 树、订阅、发布
  • Nacos / Consul / ZooKeeper / etcd：服务发现、KV / 配置浏览、健康状态、ACL

消息和数据库摆在同一个窗口里，排查问题的时候少切好几次软件。

内置 AI，还有 MCP

这是我最近用得越来越多的部分。

写 SQL 的时候不用切到浏览器去问 AI：选中一张表，用自然语言描述想查什么，直接生成 SQL；也能让它解释一段看不懂的 SQL、优化慢查询、修报错。模型可以接 Claude、OpenAI，也可以接本地 Ollama，或者任何 OpenAI 兼容的接口。生成的 SQL 在执行前会过一遍内置的安全检查，不至于让 AI 手一抖把数据改了。

更实用的是它支持 MCP（Model Context Protocol）。Claude Code、Cursor、Windsurf 这些 AI 编码工具，可以直接通过我已经配好的连接查数据库，不用再单独配一套账号密码：

权限可以在设置里控制，分只读、可读写、完全访问三档，也能限定允许访问哪些连接。让 AI 帮我排查线上问题的时候，这个确实省事。

插件是签名 + 沙箱的

dbx 的插件体系我挺喜欢：S3、Kubernetes、LDAP 这些能力都做成了插件，按需从内置商店里装，不用就完全不占地方。

更关键的是安全设计——每个插件包安装前都要验签，插件 UI 跑在沙箱里，有独立的 sidecar 进程。想自己写插件的话，官方给了 Go / TypeScript 两套 SDK，npx @dbx-app/plugin-cli 就能拉起脚手架。

顺手也给它的前端提 PR

用久了就会想去改点什么。

这个项目是开源的，我平时也会给它的前端提 PR——改改交互细节、修修样式问题。自己天天在用的工具，能参与进去改一改，感觉还是挺不一样的。也正因为看过代码，我更能确认它是认真在做的东西，不是那种套壳的”AI 数据库工具”。

最后

如果你也是一边开着 Navicat 管 MySQL、一边开着 Tiny RDM 看 Redis，真心建议试一下 dbx。

开源、免费、25 MB，试错成本几乎为零。现在它已经 3 万多 star，说明识货的人不少：

👉 https://github.com/t8y2/dbx
