RabbitMQ基础与核心概念

核心知识点速览

知识点 要点
RabbitMQ是什么 基于AMQP协议的开源消息中间件，Erlang开发
核心架构 Producer → Exchange → Queue → Consumer
四种Exchange Direct / Topic / Fanout / Headers
消息确认 生产端Confirm + 消费端ACK
持久化 Exchange持久化 + Queue持久化 + Message持久化

一、RabbitMQ整体架构

  • Producer（生产者）：发送消息的应用
  • Exchange（交换机）：消息路由中心，根据Routing Key将消息分发到不同Queue
  • Queue（队列）：消息存储容器，Consumer从这里拉取消息
  • Consumer（消费者）：接收消息的应用
  • Binding（绑定）：Exchange与Queue之间的绑定关系，定义路由规则

二、四种Exchange类型

1. Direct Exchange（直连交换机）

  • 路由规则：Routing Key 精确匹配
  • 使用场景：单播、指定队列发送
  • 示例：日志级别（error → error队列，info → info队列）

2. Topic Exchange（主题交换机）

  • 路由规则：Routing Key 通配符匹配
    • #：匹配0个或多个单词
    • *：匹配1个单词
  • 使用场景：多播、按主题分类
  • 示例：order.created → order.# 匹配 order.* 不匹配

3. Fanout Exchange（扇出交换机）

  • 路由规则：忽略Routing Key，广播到所有绑定队列
  • 使用场景：广播、全局通知
  • 示例：用户状态变更通知所有服务

4. Headers Exchange（头交换机）

  • 路由规则：匹配消息的headers属性（键值对）
  • 使用场景：复杂路由条件，x-match: all/any
  • 注意：性能较差，较少使用

三、消息确认机制

生产端确认（Publisher Confirm）

消费端确认（Consumer ACK）

  • 自动ACK：消费端收到即确认，可能丢消息
  • 手动ACK：处理成功后才确认，确保不丢
    • basicAck：确认成功
    • basicNack：处理失败，可requeue
    • basicReject：拒绝单条消息

四、消息持久化

三步缺一不可：

  1. Exchange持久化：durable=true
  2. Queue持久化：durable=true
  3. Message持久化：deliveryMode=2（PERSISTENT）

持久化消息写入磁盘后才返回确认，性能有损耗。可通过lazy queue（v3.12+默认）优化

五、常见面试题

Q1：RabbitMQ如何保证消息不丢失？

三个层面保障：

层面 措施
生产端 Confirm机制 + 失败重试
服务端 持久化（Exchange/Queue/Message） + 镜像队列
消费端 手动ACK + 幂等性处理

Q2：四种Exchange分别适合什么场景？

  • Direct：一对一精确路由，如发送给指定服务
  • Topic：按主题分类，如 order.*、user.#
  • Fanout：全局广播，如配置变更通知所有服务
  • Headers：复杂条件匹配（少用）

Q3：手动ACK和自动ACK区别？

  • 自动ACK：Consumer收到即ACK，若业务处理失败则消息丢失
  • 手动ACK：业务处理成功后才ACK，确保不丢消息，可控制重试策略
