二、Consumer Rebalance机制

2.1 触发条件

事件 说明
消费者加入新Consumer 增加消费者触发重平衡
消费者宕机/超时 session.timeout.ms内未发心跳

2.2 两种分配策略

策略 说明 特点
Range（默认） 按Topic逐个分配，分区连续分布 分配不均（订阅多个Topic时）
RoundRobin 轮询分配给消费者 均匀，重平衡影响小
Sticky (推荐) 尽量保留已有分配，减少移动 大组场景重平衡影响最小
Cooperative 协作式重平衡，分两阶段 不停顿，逐步调整

优化项 说明 效果

五、RabbitMQ vs Kafka vs RocketMQ 三选一

5.1 全面对比

对比维度 RabbitMQ Kafka RocketMQ
定位 传统消息中间件 分布式流处理平台 分布式消息中间件
语言 Erlang Java/Scala Java
吞吐 万级/s 百万级/s 十万级/s
延迟 微秒级 毫秒级 毫秒级
消息路由 ✅ 灵活（4种Exchange） ❌ 弱（按分区） ✅ 支持Tag过滤
可靠性 高（Confirm+ACK） 高（ISR+事务） 高
顺序消息 单队列 分区内保证 ✅ 全局/分区有序
延迟消息 ✅ TTL+死信/插件 ❌ 不原生支持 ✅ 内置18个级别
重复消费 需业务幂等 幂等生产者提供去重 需业务幂等
堆积能力 弱（内存型） ✅ 强（磁盘顺序写） ✅ 强
事务消息 ❌ ✅ 分布式事务 ✅ 半消息机制
运维复杂度 低 中（依赖ZK/KRaft） 中

5.2 选型建议

场景 推荐
业务解耦、服务间异步 RabbitMQ
秒杀、高并发写入 RocketMQ / Kafka
日志采集、大数据管道 Kafka
订单超时取消（延迟） RabbitMQ / RocketMQ
金融交易（强可靠性） RocketMQ
流计算（Flink对接） Kafka
消息广播、数据同步 Kafka（Compact策略）

5.3 面试核心总结

六、消息中间件面试重点清单

  1. RabbitMQ Exchange类型：Direct/Topic/Fanout/Headers
  2. 消息不丢失：Confirm + 持久化 + 手动ACK + ISR
  3. 延迟队列：TTL+DLQ vs 延迟交换机插件
  4. Kafka分区机制：分区数决定并行度
  5. ISR与HW：一致性保证核心
  6. 幂等与事务：Exactly Once实现
  7. 重平衡：Sticky Strategy降低影响
  8. 选型对比：场景驱动，没有银弹
